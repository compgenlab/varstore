# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

`varstore` is the command-line tool for the varstore sparse genotype store: it
**creates, manipulates and queries varstores, and does nothing else**. General
VCF/BAM/FASTA wrangling belongs in `cgkit` (`github.com/compgenlab/cgkit`); the
format itself -- schema, both backends, the `Calls(Query)` API, fragments and
attach -- lives in `cghts/varstore` (`github.com/compgenlab/cghts`). This repo is
flag parsing, output formatting and the conversion driver.

The commands moved here from cgkit, where they were `vcf-tovarstore`,
`vcf-varstore create`, `vcf-refblocks`, `vcf-varstore attach-refblocks`,
`vcf-varquery` and `vcf-varsummary`. There are **no aliases** for the old names.

**Module:** `github.com/compgenlab/varstore`
**Go version:** 1.24.9
**CLI framework:** Cobra

Layout:
- `cmd/varstore/` -- the CLI entry point (`--profile` handling). A server binary
  is planned beside it (`cmd/varstore-server`); keep store logic out of `cmd/` so
  both can share it.
- `internal/cli/` -- the subcommands, one file each: `convert`, `create`,
  `refblock-calc`, `refblock-attach`, `query`, `summary`.
- `internal/{buildinfo,cmdio,cmdtest,locator}` -- copied from cgkit.

Pipeline:

```
varstore convert   --out cohort/chr1 chr1.vcf.gz        pVCF -> volume (one per chromosome)
varstore create    cohort/                              volumes -> one varstore
varstore refblock-calc --roster cohort --out frags/S1 S1.g.vcf.gz   per-sample gVCF -> fragment
varstore refblock-attach cohort/ frags/                 fragments -> ref_blocks
varstore query     cohort --variant chr1:1000:A:T       genotypes
varstore summary   cohort                               what a store holds
```

The on-disk metadata keys keep their `cgkit.` prefix (`cgkit.source`,
`cgkit.meta.*`): they are part of the format, defined in cghts, and predate this
repo.

## Dependency on cghts

The store, VCF I/O and the site-selector grammar come from
`github.com/compgenlab/cghts` (`varstore`, `vcf`, `iosource`, `htsio/*`). When the
store needs to change, change it there first and re-pin; a change that needs a
flag *and* store support is two commits in two repos, in that order.

How the `cghts` dependency resolves, by context:
- **Local builds** use the `go.work` workspace (parent dir, untracked) that joins
  a sibling `cghts` checkout, so you build against your live local `cghts` tree. The
  `Makefile` deliberately does **not** set `GOWORK=off`.
- **Remote/CI builds** (no `go.work` present) use the **latest released cghts from
  GitHub**: the GitHub Actions workflow runs `go get github.com/compgenlab/cghts@latest`
  before vet/test/build, with `GOPRIVATE=github.com/compgenlab/*` so a freshly
  pushed cghts tag is fetched directly from GitHub (no module-proxy/sumdb lag).
- The committed `go.mod` pin is the fallback for `go install` users and the
  source archive; keep it current with `make bump-cghts`.
- **Building against unreleased cghts.** A feature spanning both repos can pin a
  cghts *commit* instead of a tag:
  `GOWORK=off go get github.com/compgenlab/cghts@<sha> && GOWORK=off go mod tidy`,
  which writes a pseudo-version (`v0.12.1-0.<date>-<sha>`). CI honours any pin
  carrying a `-` (pseudo-version or pre-release) rather than following `@latest`,
  which skips those and would build the branch against code lacking what it needs;
  a release pin (`vX.Y.Z`) still means `@latest`. Re-pin as the cghts side moves.
  `make release-check` **refuses** a pseudo-version pin, so tag cghts and
  `make bump-cghts` before releasing.

### Cutting a release
The cghts tag must land on GitHub before varstore builds against it:
1. **cghts**: tag `vX.Y.Z` on `main`, push the tag.
2. **varstore**: `make bump-cghts` (pins `go.mod` to the new cghts), commit
   `go.mod`/`go.sum`, push. CI's `go get cghts@latest` then resolves the same tag.


## Remote inputs

Inputs may be local paths, `http(s)://` URLs or `s3://` objects; **outputs are
local**, with one exception: `varstore convert --out s3://bucket/store` writes a
varstore straight to S3 through cghts's `varstore.Sink` (`varstore/sinks3`,
blank-imported in `internal/cli/convert.go`, refused up front via `varstore.CanWrite`
when no sink for the scheme is linked). Dispatch is cghts's `iosource`, and index sidecars resolve over
the same transport as the data, so an indexed region query still seeks.

- The `s3://` blank import lives in **`internal/locator`**, a leaf package, not in
  `main.go`. `main` is not linked into `go test ./internal/...`, so a test
  asserting the "no transport registered (registered: s3)" message would pass
  there while the shipped binary said otherwise; keeping it in a package the
  tests link makes the test the guard on the import. This is why varstore carries
  the AWS SDK.
- `internal/locator.IsRemote` wraps `iosource.IsRemote` rather than
  reimplementing it. varstore must classify a locator exactly as the library will
  dispatch it; a classifier that disagreed by one edge case (a Windows drive
  letter is not a scheme) would not fail loudly, it would open the wrong thing.
- **`targets.go` classifies scheme-first, then `os.Stat`.** A URL cannot be
  stat'd, and a stat-first rule would demote it to an inline selector, which
  parses as a contig name and matches nothing — an empty result rather than an
  error. Only values containing `://` past the first character change meaning,
  and nothing in the selector grammar can look like that, so a mistyped locus
  still gets a locus error and `HLA-A*01:01:01:01` is untouched. Both pinned by
  tests; this is the single riskiest change in the remote work.
- **Outputs are refused by name**, via `locator.CheckLocalOutput`, always *after*
  a command's stdout branch or `-` breaks. A VCF writer (`query --format vcf`)
  has no writer-side equivalent of a byte source. A varstore is the exception because
  every table is written strictly forward with its footer last, so each one can
  be a multipart upload that becomes visible only when it completes; that is a
  property of the store's sink, not a general remote-write facility.
- Costs stated rather than hidden: a *streaming* read of a remote object
  transfers the whole thing (no index to skip with), and an unindexed remote VCF
  is re-read on every query; `varstore summary` says whether an index was found.
- Deliberately **not** covered: remote writes other than a varstore, `gs://`.

## Subcommands

- **gVCF support**: `varstore query` reads reference blocks as the coverage they are — one reference row per block per sample (never one per base), `alt` `.`, `min_dp` the block's own `MIN_DP`, `dp` `.` since a block measures no single base, `gq` from `RGQ`. A position no variant record mentions is answerable when a block covers it; a **gap** between blocks is not, because nothing was reported there. `Gate.Admits` prefers `MinDP` over `DP`, which is load-bearing rather than tidy: `Missing` passes every gate by design, so a block-derived call would otherwise be admitted unconditionally. **`varstore convert` refuses a gVCF** — it used to produce a store with `<NON_REF>` in the sites catalog, `AC`/`AN` counting a block allele, and every block reduced to its first base, all silently. The refusal keys on **a reference block record** (`rec.IsRefBlock()`), not on the header: a joint-genotyped cohort VCF — a DRAGEN msVCF, a GATK `GenotypeGVCFs` callset — keeps the `##ALT=<ID=NON_REF>` line inherited from its source gVCFs while containing no blocks, and `##ALT=<ID=*>` declares the ordinary spanning-deletion allele, so `isGvcfHeader` rejected exactly the input this command is for. VCF 4.5 makes that unfixable at the header level: the gVCF unspecified allele and the spanning-deletion allele are the same ALT ID. cgkit's `vcf-strip` still must decide from the header (it writes its header before reading a record); `varstore convert` need not, since a failed conversion `Discard()`s. A mixed `G,<NON_REF>` record is a variant record and converts, with the block allele masked out of the catalog, the calls and AC the way any non-focal alternate is (`-v` counts them). Conversion is deferred to a later release and is a **cohort** operation -- the unit is a *set* of gVCFs merged together, since one gVCF is single-sample and a one-sample store answers nothing that querying the gVCF directly does not. See `PLAN.md` §2.
- `varstore convert` — Convert one or more VCFs into a varstore **volume**: a sparse Parquet genotype store (several inputs is how whole-genome callsets ship: one per chromosome). Formerly `vcf-toparquet`, renamed because the name is the *store* and Parquet is only today's encoding behind cghts's interface; the user docs are `docs/convert.md`. Flags beyond those discussed below: `--shard-sites N` splits every table into aligned coordinate shards indexed by the manifest (0, the default, writes one file per table); catalog runs break where depth crosses a band boundary so each run's `min_dp` bounds the whole of it, and the boundaries are the `--min-dp` gates `varstore query --hom-ref` answers **exactly** -- a store keeps only a run's floor, so a gate inside a band returns a subset of the source VCF's `0/0` calls (never a superset), and `-v` says so. Bands default to geometric, `--min-dp × --depth-ratio^k` (1.5: 10,15,22,33,50,...), which bounds that loss at any gate *g* to sites below 1.5*g*; `--depth-bands 10,20,30` names them outright instead (the two are exclusive) and `--depth-ratio 0` leaves runs unbanded. The manifest records the generated list, which is what `varstore create` compares; `--info`/`--format` capture named INFO fields into typed `info_*` columns on the catalog and FORMAT fields into `fmt_*` columns on calls (globs allowed; FORMAT is off by default because calls carries ~100x the rows); `--out s3://...` writes remotely (see Remote inputs). Inputs must carry **exactly the same samples**; differing column order is **remapped**, because genotype columns are positional and getting that wrong silently attributes every genotype to the wrong person. A set mismatch errors, naming what differs. Inputs must not overlap (no revisiting a chromosome, no going backwards within one) since that would duplicate sites and split AC/AN; supplying them in coordinate order is not required for correctness but keeps pruning tight (~1.8x on a locus query). A failed conversion calls `Writer.Discard()` so no partial store is left to look valid or block the retry through the overwrite guard — including the "no DP field" refusal, which used to run *after* `Writer.Close()` and so left all three members on disk, whereupon the overwrite guard blocked the very `--no-callable` retry its error message asks for. The tables: `calls.parquet` (one row per ALT-carrying genotype), `catalog.parquet` (one row per interrogated site, carrying **AC/AN** allele counts alongside `n_carriers`/`n_called`/`n_lowdp` sample counts — these are not interchangeable: a 1/1 genotype is one carrier but two alt alleles, so AC ≥ n_carriers whenever a homozygote is present, and AN counts alleles ungated while n_called counts samples passing `--min-dp`. AC/AN are recomputed from the store's own samples rather than copied from source INFO, which would be wrong after splitting multiallelics or converting a cohort subset, and they are computed outside the `--no-callable` guard since allele counts are a property of genotypes, not coverage), `catalog_runs.parquet` (contiguous runs of covered sites per sample). **A store is a directory** — `cohort/{calls,catalog,catalog_runs}.parquet` plus `manifest.json.gz` — and a trailing `/` on `--out` is optional and meaningless. The former filename-prefix form is gone; keeping both meant every path decision first had to guess which was meant, and `TrimStoreSuffix` had to consult the filesystem, which cannot work for a remote locator. `varstore query` accepts the directory, either spelling, or any member path; `varstore.TrimStoreSuffix` owns that and no longer touches the filesystem. **The manifest is what makes a store readable rather than merely present**: written last by `Writer.Finish`, required at open, with each member's recorded row count checked against that member's own parquet footer — the only thing that catches a well-formed member belonging to a *different* conversion. It carries a per-chromosome census accumulated by the writer *as it writes*, so it records rows rather than intent; that matters because `cgkit.source` and `cgkit.contigs` are stamped before the first record is read, so a store covering 3 of 22 chromosomes still names all 22 inputs and declares all 22 contigs. There is **no escape hatch**: an unfinished store answers "not assayed" for everything it never reached, which is indistinguishable from the honest answer for a position the source never reported. Stores from before manifests must be re-converted; `varstore summary` is how you find out why one was refused. **Metadata (`--meta-*`) records what a store *is*, where everything else records how it was made.** A whole-genome callset converts from 24 per-chromosome VCFs into one store that can name its 24 input filenames but not the release they collectively are — and those filenames stop identifying anything once the store moves. The assembly is the same gap in a worse form: `##contig` lengths *imply* GRCh37 vs GRCh38, but a store read against the wrong assumption does not fail, it answers with coordinates that mean something else. Seven keys have an agreed meaning (`dataset`, `reference`, `caller`, `accession`, `url`, `version`, `description`), each with a `--meta-<key>` flag **generated from `varstore.ReservedMetaKeys`** so the flag names and the keys they write cannot drift; `--meta KEY=VALUE` records anything else. It lands in the same two places provenance already does — the manifest's `meta` object and the calls file's Parquet metadata, namespaced under `cgkit.meta.` so a supplied key can never shadow one the writer vouches for (`--meta source=x` does not become `cgkit.source`). **Values are recorded verbatim and never validated** — varstore cannot know whether `GRCh38` is true, and normalizing it would turn the caller's claim into varstore's — while **keys are** validated to lowercase `[a-z0-9_-]`, since a key must survive a Parquet metadata key, a JSON member and a grep (the dot is excluded because `MetaPrefix` uses it as a separator). A key given twice, by either spelling, is an **error rather than last-wins**: which of two conflicting claims gets recorded must not depend on flag order. Validation runs in the CLI pre-flight *before* `EnsureStoreDir` so a typo leaves no directory behind, and again in `NewWriter` before it touches disk, since its next act is removing the previous run's manifest — a key rejected any later would have unmade a readable store in order to refuse the run meant to replace it. Absent metadata is **omitted entirely, never written as `{}`**: absent means "not stated", not "stated as nothing", which is also what keeps a metadata-free conversion byte-identical to one from before the field existed. `varstore summary` prints all of it (reserved keys first in library order, then extras alphabetically), `--format json` emits it verbatim, and `varstore query -v` reports only `dataset` and `reference` — the two that change how a result should be read; the rest is catalogue. Conversion **refuses to overwrite an existing store** — any one of the members already present under `--out` stops it and asks for `--force`; writing truncates all three, and a half-replaced set is worse than either whole outcome. The guard keys on the members, so an existing directory holding unrelated files is fine and its contents are left alone. The catalog table is **not** derivable from the calls: taking distinct loci out of the calls only recovers every site when the store holds an entire joint callset, and over a sample subset the sites nobody in that subset carries vanish silently, so a later query reports "never interrogated" for a position that was in fact observed and reference. Records are normalized to one variant per row (multiallelics split, focal allele recoded to 1, other alternates masked to `.` so a `1/2` sample is correctly a carrier of both; AD taken per allele, not summed). Indels are **not** left-aligned. A site counts as called only when the caller actually made a call there *and* DP ≥ `--min-dp` — `./.` at high depth is a declined call, not a covered one. **The catalog_runs table records runs of *catalog sites* at which a sample was called; the interval form is a compression of that per-site fact and claims nothing about the bases in between.** A plain VCF reports variants and asserts nothing about any other position, so the sites catalog is the exact boundary of what is answerable: an off-catalog locus is `not_assayed` for every sample, never a set of reference calls, even where run intervals bracket it (`Classify` returns early on the catalog check for precisely this reason, and `varstore query` warns). Only a store carrying the optional `ref_blocks` table answers off-catalog -- for exact loci only, never at a catalog site (cghts#53) -- and `varstore query` then notes rather than warns, and labels each `0/0` by `ref_source`. See the GVCF memory. `-v/--verbose` reports progress **as a `chrom:pos` coordinate** rather than a record count alone — counts advance at the rate variants are called, so on a sparse input a quiet stretch is indistinguishable from a stall, whereas a position can be checked against the contig length. The chromosome-transition line carries it too, since the periodic tick only fires every 100,000 records and a smaller contig would otherwise name itself and go silent. Plus a per-chromosome trace and a conversion summary, all on stderr — notably a census of which of DP/GQ/AD the input actually carries, since a gate can only act on a field the data has.
- `varstore refblock-calc <sample.g.vcf.gz> --roster STORE --out DIR` — Extract one sample's gVCF reference blocks into a **fragment** for a store's `ref_blocks` table: single-sample, streaming, one job per gVCF. Genotypes still come from the pVCF; a fragment holds only spans where the sample was observed reference. Blocks below `--min-dp` are dropped; adjacent blocks in one depth band merge (keeping the lowest `MIN_DP`) across uncovered stretches of at most `--max-gap` (default 10); `--passthrough` keeps the source's blocks. A **variant record or a no-call block is never bridged** -- its gap is what stops coverage claiming reference where the sample carries something. `--roster` is checked first: the sample must be on it, and `--min-dp`/bands default to the store's and are **refused if they differ**, since an unattachable fragment is one wasted job in ten thousand. Output is cghts's fragment layout (one Parquet per chromosome + `fragment.json` written last); a finished fragment is kept unless `--force`.
- `varstore refblock-attach <store> [fragment ...]` — Merge fragments into each volume's `ref_blocks` via cghts's `AttachRefBlocks`, then (on an archive) rewrite `varstore.json.gz` with `BuildStore`, since volumes and archive must agree on `RefBlocks`. An argument is a fragment or a local directory of them; `--from FILE` lists them. The first attach builds the table; after that **`--rebuild`** rebuilds it from the given fragments alone, and **`--replace S1,S2`** keeps everyone else's existing blocks and swaps in these samples' fragments (a replaced sample with no fragment is removed) -- one merge either way, the existing table being just another input. Every file a changed sample appears in is rewritten either way, because the table is sorted by position across samples. Merged in batches of `--batch` (default 100) through local intermediates (`--tmp`); output is a new file generation and each volume's manifest is rewritten last, so an interrupted run leaves the volume as it was. Every chromosome a fragment covers becomes answerable through cghts's `AttachRefBlocksToStore`: one with no catalog site gets a blocks-only volume on an archive, or joins a single volume. `TestAttachedStoreAnswersOffCatalogLikeTheGvcfs` is the end-to-end check: with `--passthrough` fragments, the store's off-catalog `0/0` calls equal the gVCFs' own.
- `varstore create <store-dir> [volume ...]` — Combine existing volumes into one **varstore**, read as one. Whole-genome data converts to one volume per chromosome (`varstore convert --out cohort/chr1 chr1.vcf.gz`, ...), and this writes `varstore.json.gz` over them via `varstore.BuildStore`; given no volumes it takes every readable volume subdirectory in name order, and a volume named with a scheme is used as given so volumes may live apart. It **refuses** volumes that differ in samples or sample order, `--min-dp` or `--depth-bands`, or that share a chromosome, because a store answering with a different population per chromosome is worse than one that cannot be built. The archive is also what keeps `--shard-sites` affordable: each volume's shard index covers only its own chromosome, and a query opens only the volumes it touches. Everything that reads a store (`varstore query`, `varstore summary`) accepts an archive, a bare volume, or a VCF. The hierarchy is varstore → volume → shard, all split by coordinate; the tables split by data kind and every shard has all of them.
- `varstore summary` — Describe a store or a VCF without querying genotypes: samples, contigs, provenance, per-chromosome census. **The default report never reads a record** — O(header) on both backends, so it is instant against a 200 GB VCF — and `--samples`/`--counts`/`--sites` are the opt-in passes. That is a hard guarantee with a test to match (a fixture whose header is valid and whose records are not, so anything reading past the header fails). A store's facts come from its manifest; a VCF has none, because it is not a conversion, and the report says so rather than fabricating a `--min-dp` or a creation date. For an *indexed* VCF the contigs that carry records come from the tabix index for free — the cheapest useful thing a VCF summary can report; exact record counts are not recoverable from an index and are not estimated from one. `--format json` emits a store's manifest verbatim, which is the promise that makes gzipping it acceptable. It must also work on a store that cannot be *opened* for querying, since with no escape hatch for a missing manifest this is the only way to learn why one was refused. With `ref_blocks` it says **whose gVCF fragments were attached** (`from 9,800 of 10,000 samples; not attached: ...`), read from the manifest's `ref_block_samples` (cghts `RefBlockSamples()`): a sample never attached answers `not_assayed` off the catalog exactly like one whose gVCF reported nothing there, and only this line tells them apart. On an archive the list is stated once when volumes agree and per volume when they do not (a replace that died partway); a table attached before the list was recorded says so and suggests `refblock-attach --rebuild`. `--format json` on an archive emits the store manifest.
- `varstore query` — Query genotypes over either a VCF or a `varstore convert` store, chosen by path or `--store`. **Two independent axes**: `--variant` selects sites, `--sample` selects subjects, and they compose — naming both asks what those subjects' genotypes are at those sites, which used to be a hard error ("separate modes"). An axis left unnamed is unrestricted, not empty. `--variant` is the **only** site selector (there is no `--region`) and takes `chr1`, `chr1:1000-2000`, `chr1:1000`, `chr1:1000:A:T`, or a **file** — VCF/BCF, BED, or whitespace-separated `chrom pos [ref alt]` — detected from content, with BED and site lists told apart by whether column 3 is numeric (a BED end always is, a REF allele never is). A value is a file when one exists by that name, so a mistyped locus still gets a locus error. An exact locus additionally requires non-numeric REF/ALT, which is what lets contig names carry colons (`HLA-A*01:01:01:01` splits into four fields too, but its tail is numeric); anything matching no shape is a contig name taken whole, and a target that matched nothing is reported so a malformed locus does not read as a real negative. BED is 0-based half-open where site lists and VCF are 1-based, so a misdetection would shift coordinates rather than fail — hence `-v` names the format read and a file yielding no targets is an error. cgkit's `vcf-gtcount --sites` shares the parser (`varstore.ParseTargets` in cghts), so one file serves both. **Chromosome naming is auto-converted**: UCSC (`chr22`), Ensembl (`22`) and NCBI RefSeq (`NC_000022.11`) spellings all resolve, via cghts's `CanonicalContig`/`ContigConverter`. Comparisons use canonical identity, and tabix lookups resolve against the index's own `RefNames()` — tabix matches names verbatim, so a bare `22` against a `chr22` index used to fail with `unknown reference`. Conversion preserves the source's own spelling in the store rather than rewriting it. A contig the file lacks is an absence (no rows plus a warning), independent of whether the file is indexed; an unresolvable `--region` is an error, since that names a contig the caller asserts exists. `-v/--verbose` reports the chosen backend, the store's conversion provenance, per-variant AC/AN/AF, the ALT-call and hom-ref row counts, and how many calls the quality gate actually excluded — including a warning when the gate could not act because the field is absent, and when `--min-dp` differs from the value the store's runs were built at. All verbose output goes to stderr so the tabular stream stays parseable. A `--variant` **span selects by record overlap**, so a region query returns a deletion or gVCF block that begins before it and reaches in; the extent is stored per row as `ref_end` and computed from `len(REF)`, `INFO/END`, `SVLEN` and `FORMAT/LEN`. A store converted before that column existed selects on position alone and reports `HasRefSpans() == false`, which is a different answer rather than a slower one. **Queries prune row groups rather than scanning the whole file** (`cghts/varstore/prune.go`): input is coordinate-sorted and written in stream order, so parquet's per-group min/max on `pos` are tight, and a locus lookup skips every group that cannot contain it — measured 3.05x on a two-chromosome 1KG store (479ms to 157ms). **There are now reproducible benchmarks** (`internal/cli/bench_test.go`) over a seeded generated corpus rather than uncommitted 1KG data -- `go test -bench BenchmarkQueryPanel|BenchmarkStoreVsVcf`, scaled by `CGKIT_BENCH_SAMPLES`/`SITES`/`ROWGROUP`. Two findings worth knowing: one bulk query is ~349x a per-locus loop at 1000 targets and stays *flat* (7ms to 19ms across a thousandfold target increase) where the loop is linear, which is the measurement the single-`Calls` API was argued for; and against a **tabix-indexed** VCF a single-locus lookup is only ~1.9x faster, not the ~40x an unindexed VCF suggests -- the unindexed figure measures a file nothing can seek in, and quoting it would flatter the store. The 18x at 100 loci is partly ours: `VcfStore` only seeks for a single locus or region, so a multi-locus query scans and the index goes unused. Note also that `--row-group-size` at its 250,000 default puts a modest corpus in ONE row group, where position statistics can never exclude it and every lookup scans everything. Filters are conservative in one direction: they may keep a group holding nothing, never skip one holding a match, and the per-row checks are unchanged, so pruning can only affect how much is read. Chromosome bounds are only used when a group holds exactly one chromosome, since the statistics are lexicographic while chromosome names are not ordered that way. Note `--sample` queries cannot be pruned this way: every sample appears in nearly every row group, so the sample_id bloom filter always says maybe — making those fast would need a sample-major sort, which conflicts with the (chrom,pos) sort. There is deliberately **no `--classify`, no `--min-gq` and no `--region`**. The four internal states (carrier / uncertain / non-carrier / not-assayed) remain library machinery in `varstore.Classify`, because reconstructing a `0/0` from a store requires them, but they are not a CLI vocabulary: the genotype in the output already says which case occurred, so there is no state column to interpret. `--min-gq` went because callable runs are built from depth alone — a store retains no GQ for a genotype it never wrote down, so it could not gate a reference call where a VCF would, and the backends disagreed about which samples were reference (a real bug, caught by `TestHomRefBackendsAgreeUnderTheGate`). The `gq` column is still emitted, so filter downstream. The backends must agree: verified identical on 3,202 1KG samples, including at the worst-covered site in BRCA1. For that equivalence the query `--min-dp` should match the conversion `--min-dp`, since the Parquet side baked that threshold into its callable regions. An incomplete store (missing catalog/catalog_runs, or built with `--no-callable`) makes `--hom-ref` return `ErrNotClassifiable` rather than degrade — reporting an unobserved sample as reference would invent an observation. `--hom-ref` switches from "only the valid ALT calls" (the default) to "every interrogated site" (the `gt` column separates them): in `--variant` mode the samples that are 0/0 at the locus, in `--sample` mode the catalog sites that subject was 0/0 at. It is **stricter than the internal `non_carrier` state**, and the difference is the whole point: at a multiallelic record a 0/2 sample is not a carrier of allele 1, but it is not reference either, so it appears under neither — emitting `0/0` for it would be a genotype the source never contained. Both backends therefore key the exclusion on the source *record* (`Locus.Record()`, i.e. chrom+pos+ref), not the split locus, and the disqualifying ALT call is looked up ungated, since a below-gate ALT makes a sample an uncertain carrier rather than a reference observation. The same bounds apply as to any reference claim: the gate must admit the reference call (a 0/0 at DP 3 under `--min-dp 10` is not an observation worth making), an off-catalog locus yields nothing, and an incomplete store returns `ErrNotClassifiable` in both modes. One asymmetry is unavoidable and is the one place the backends do not agree byte-for-byte: a store keeps only ALT genotypes, so a reference call recovered from one is a synthesized `0/0` with no DP/AD/GQ and no recoverable ploidy or phasing, where the same query against a VCF reports the recorded genotype and its quality fields — *which* rows appear is identical, and `-v` says so. `--format list` is refused with `--hom-ref`, since bare sample ids cannot say which are carriers and which are reference. In `--sample` mode this walks the whole sites catalog — roughly one row per variant in the source — so `--region` is what keeps it bounded. `--format vcf` emits a genotype matrix — one record per site, one column per sample — through cghts's `VcfWriter`, so `-o NAME.vcf.gz` bgzips and `--tbi` indexes. It **implies `--hom-ref`**, because a matrix that cannot tell an observed `0/0` from an unobserved `./.` asserts far less than the data supports, and it therefore inherits the `ErrNotClassifiable` refusal. `INFO` carries `AC`/`AN`/`AF`/`NS`/`nhomalt` **recomputed over the samples in the file** rather than copied from the store, since over a subset the catalog's counts are for the wrong denominator; a header note records that `AN` is depth-gated and so can differ from the store's own ungated `AN`. Only one locus is buffered at a time, which the store-order guarantee makes possible. **Every non-VCF output shares one tabular layout** — `chrom pos ref alt sample gt dp min_dp ad_ref ad_alt gq ref_source` — so results concatenate, sort and cut the same way whichever selectors were named; `--sample` used to lead with the sample column. Rows stream rather than accumulate, and arrive in the **store's own order** — contig order as written, *not* lexicographic, since sorting `chrom` as a string puts `chr10` before `chr2` and yields an unindexable VCF. Within a locus they are ordered by sample. `min_dp` is the tightest lower bound on depth the backend can vouch for: the recorded depth where there is one, the conversion `--min-dp` for a reference call reconstructed from a store (the run it came from is the evidence the site was covered), `.` where nothing is known. Writing that threshold into `dp` instead would assert a depth the data never had, which is the same class of error as writing `0/0` for an unassayed sample.
